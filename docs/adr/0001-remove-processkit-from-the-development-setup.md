# 0001. Remove processkit from the development setup

- **Status:** Accepted
- **Date:** 2026-11-11
- **Deciders:** project owner (issue #505)

## Context

This repository used processkit v0.28.8 for its own development: an MCP
gateway, 404 skill files, `pk-*` commands, derived agents, hooks, a
per-turn compliance contract in `AGENTS.md`, and entity records under
`context/` (decisions, work items, notes, discussions, logs). The mirrored
upstream templates alone were 27,727 of the 29,922 tracked files under
`context/`.

The company now delivers its engineering rules as versioned standards
(`projectious-work/standards`), which each repository installs. The
coordination repository removed processkit on 2026-10-29
(`DEC-20261029_1040-AgileFalcon` there) and asked the product repositories
to follow. processkit v1 is being specified elsewhere.

aibox also supports processkit as a product feature (`mode = "processkit"`).
That is product code and is a separate question.

## Decision

Remove processkit from this repository's own development setup.

1. Tag the last state with the full installation as `processkit-final`.
2. Move the records from `context/` to `archive/processkit/` as plain,
   read-only files: decisions, artifacts, work items, notes, discussions,
   logs, actors, roles, bindings, team members, scopes, gates, migrations
   and earlier archives.
3. Delete the machinery: template mirrors, skills, schemas, state machines,
   the MCP manifest, the provenance file, indexes and the `pk-doctor`
   allowlist.
4. Remove the `pk-*` skills and the processkit sections of `AGENTS.md`, and
   set `aibox.toml` to `mode = "harness-only"`.
5. Record new architecture decisions as ADRs in this directory. Track work
   in GitHub issues and pull requests.

The product support for `mode = "processkit"` stays unchanged.

## Consequences

- The repository loses about 28,000 tracked files, and agents no longer load
  a compliance contract on every turn.
- There are no processkit MCP tools, hooks or entity validation here. The
  former records are frozen history; nothing adds to them.
- `DEC-*` identifiers in the specification, the development notes and commit
  messages still resolve, now under `archive/processkit/decisions/`. Paths
  inside the archived records still say `context/…`.
- Chapter 21 of the v1 specification named processkit DecisionRecords as the
  place for architecture decisions and `route_task` as a reviewer proposal
  source. It now names this directory, and no routing tool.
- The generated, untracked harness files (`.claude/`, `.mcp.json`,
  `.codex/`) keep their processkit entries until `aibox sync` runs on the
  host with the new `aibox.toml`. `aibox.lock` and `.devcontainer/` are
  regenerated by the same run.
- The full former setup can be restored from the tag `processkit-final`.
