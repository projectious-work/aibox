# aibox v1.0.0-alpha.1

aibox v1 alpha introduces an explicit, provider-neutral control plane for
building immutable AI workspace images and deploying them through Compose or
Kubernetes. This is an evaluation release: v0 remains the supported stable
line, and infrastructure provisioning remains outside aibox.

## Added

- Versioned v1alpha1 contracts for workspace images, fleets, deployment
  targets and records, backend descriptors, and connection targets.
- Deterministic configuration compilation, explicit image builds, deployment
  planning, apply/status/log/connect/destroy lifecycles, and project-local
  deployment receipts.
- Compose and Kubernetes backends with ownership validation, workload-first
  apply ordering, guarded destruction, drift recovery, ingress boundaries, and
  explicit exec or port-forward connections.
- Exact-pinned processkit `v1.0.0-alpha.3` delegation through its signed,
  opaque request/result protocol, including interruption recovery and
  secret-safety checks.
- Previewable v0-to-v1 configuration preparation with exact backup and
  explicit restoration.

## Changed

- V1 deployment operations are separated from image construction and
  connection establishment.
- Release readiness fails closed until live disposable-cluster evidence is
  bound to the exact candidate commit and binary digest.
- V1 prereleases use the same protected-branch, two-phase, evidence-bound
  release process as v0, with a mandatory pre-publication documentation gate.
- Maintained v0 add-on installer hardening is ported to v1, including verified
  Node, Go, Typst, and AWS inputs and ARM64 Node compatibility.

## Fixed

- Kubernetes apply no longer publishes ingress or DNS changes before workload
  success.
- Kubernetes destroy performs complete ownership validation before its first
  mutation and records durable progress.
- M7c evidence rejects missing, duplicate, unknown, unexecuted, stale, or
  unbound scenarios and invalid timestamps.
- Kubernetes ownership digests are encoded as valid metadata labels, and live
  Ingress/Gateway observation retains the endpoint fields required for strict
  post-apply verification.
- The rebuilt companion's rootless kind lifecycle uses delegated systemd
  scopes, a nested-runtime-safe containerd snapshotter, and bounded kubeadm
  startup timing.

## Known limitations

- This alpha consumes existing infrastructure; it does not provision clusters,
  networks, DNS zones, cloud accounts, or identities.
- Practical conversion of arbitrary v0 configurations is incomplete. The
  alpha provides a reversible boundary, not automatic semantic migration.
- `uv` base-image refresh work is deferred to
  `BACK-20260728_1132-ShinyPrairie-refresh-uv-base-image-pin`.

## Install

After all four platform assets are published:

```bash
curl -fsSL https://raw.githubusercontent.com/projectious-work/aibox/main/scripts/install.sh |
  VERSION=1.0.0-alpha.1 bash
aibox --version
```

## Roll back

Destroy any v1 deployment that should be removed using the guarded v1 CLI,
then reinstall the chosen stable v0 release by exact version:

```bash
curl -fsSL https://raw.githubusercontent.com/projectious-work/aibox/main/scripts/install.sh |
  VERSION=0.28.17 bash
```

Reinstalling the binary does not delete v1 deployments or their receipts.
