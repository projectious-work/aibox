# Layered settings and diagnostic sinks: acceptance journeys

Normative. Each journey is a black-box test of the built `aibox` executable
through the CLI or through an MCP client on stdio. Identifiers, values,
codes and paths come from `interfaces.json`.

## Common setup

- Every journey runs as an ordinary user, **not root**, on a machine or in a
  container that has no `/etc/aibox/settings.json`. A journey marked **root**
  instead runs in a disposable container, where the test writes
  `/etc/aibox/settings.json` as root and then runs aibox as an ordinary user.
- Every journey uses a fresh temporary directory as `HOME`. The environment
  holds only `HOME`, `PATH` and what the journey adds. `XDG_CONFIG_HOME` and
  `XDG_STATE_HOME` are unset unless the journey sets them. No journey reads
  the developer's own settings.
- "Project P" is a copy of `fixtures/project-minimal`; "Project W" is a copy
  of `fixtures/project-workspace`. Copies live in a temporary directory
  **outside** `HOME`, unless the journey says otherwise.
- Environment files and settings files are created with mode 0600.
- "View" means `aibox inspect --context local --project <project>
  --effective-config --format json --log-format jsonl`. `entry(k)` is the
  element of `data.configuration` with `key` k. "Settings entries" are the
  entries after the native entries.
- "Rejected with reason R" means: exit 2; stdout holds one error envelope
  with `operation` `invalid_request`, `outcome` `failed` and error code
  `invalid_input` when `--format json` was given, and is empty otherwise;
  stderr holds exactly one `settings.rejected` event, in `jsonl`, with
  `fields.reason` R, `sequence` 0 and the envelope's `requestId`; and no
  `operation.started` event. Commands in rejection journeys are run as
  `aibox inspect --project <P> --format json --log-format jsonl` plus what
  the journey adds.
- Unless stated, expect exit 0, `outcome` `succeeded`, and a stdout that is
  exactly one JSON document that validates against
  `schemas/operation-result.schema.json`.
